# WebTvLive 开发计划

> 目标：自研一款「基于 WebView 的安卓直播电视 App」，思路对齐参考项目 `WebViewTvLive`（用内置浏览器一键打开各电视台**官方直播网页**，自动定位网页里的 `<video>` 并进入全屏，做成"像传统电视一样换台"的体验）。本 App **不采集/不存储/不转发任何视频流**，只做官网页面的嵌套展示。

## 1. 产品原理回顾（决定技术选型）

```
用户选台 → GeckoSession.stop()  // 先停止上一路页面
        → GeckoSession.loadUri(官网直播页URL)
        → 内置 WebExtension 在官网页面及播放器 iframe 中运行适配脚本
        → JS 轮询找 <video> → 自动播放/取消静音/全屏样式 + native messaging 心跳
        → 原生层收到 playing 消息 → 隐藏加载遮罩
        → 超过"最长加载时间"无心跳 → 自动切下一个源并刷新
```

三个真正的技术难点（复刻成败在此，不在功能多少）：
1. **自动全屏可靠性**：不同网站进全屏方式不同 → JS 请求全屏 + 模拟按 `F` 键 + 模拟双击，多管齐下、重试若干次。
2. **内核兼容性**：安卓设备 WebView 版本碎片化严重；目标电视的 WebView 66 已确认不兼容 CCTV 当前播放器，因此改用随 APK 分发的 GeckoView 153。
3. **频道源服务端化**：官网 URL 会变 → 频道表放远程 JSON，客户端定期拉取，用户无感更新。

| 领域 | 选型 | 说明 |

- [x] 封装 GeckoView：桌面 UA、设备视口、JavaScript、自动播放权限、生命周期与页面状态日志
- [x] 内置 WebExtension 通过 native messaging 回传 `playing` 和诊断信息
- [x] `assets/webextension/player_adapter.js`：在主页面及 iframe 中轮询播放器，逐层隐藏旁支、全屏铺满、强制播放并回传心跳
- [x] 自动加载 `https://tv.cctv.com/live/cctv13/`（`HOME_URL` 常量）
- [x] 返回键两次退出（`onKeyDown` 拦 `KEYCODE_BACK`，2s 内两次 `finish()`）

**验收**：✅ 模拟器可启动；小米电视（Android 9 / armeabi-v7a）实测自动起播、视频铺满全屏、菜单和换台正常，3 分钟连续播放无旧 WebView 周期性媒体错误。

> **全屏方案关键结论（最初系统 WebView 实现的踩坑记录，当前已迁移到 WebExtension，务必保留）**：
> 1. **不能只用 `<style>` 铺满**：目标 `<video>` 的祖先元素带 `transform`，会让 `position:fixed` 不再相对视口 → 必须**清除祖先链的 `transform/filter/perspective`**。
> 2. **不能依赖 `<style>` 的 `!important`**：CCTV 播放器脚本每帧用**内联样式**把 video 尺寸改回 `1138×640`，内联优先级更高 → 必须**每秒把 `!important` 内联样式直接写到 video 元素上**（`style.setProperty(k,v,'important')`）压过站点脚本。
> 3. **隐藏网页外壳**：把 body 下不在「video→body 祖先链」上的顶层节点 `display:none`，只留播放器这一支 DOM，导航栏/边栏才会消失。
> 4. **浏览器视口必须使用设备视口**：桌面 UA 配合桌面缩放视口会使 `100vw/100vh` 映射后留黑边；GeckoView 当前使用桌面 UA + mobile viewport。
> 5. 全屏靠 WebExtension 在主页面和播放器 iframe 中每秒维护内联样式实现；必须沿播放器祖先链逐层隐藏旁支，不能只处理 body 顶层节点。

### M1 — 频道体系（换台）
**目标**：内置/远程频道表，列表选台、上下键换台、多源切换。

- [ ] 数据模型：`Channel(name, group, urls: List<String>)`、`ChannelGroup`、`Playlist`

- [ ] `PlaylistManager`：
  - [ ] 先内置一份本地 JSON（`assets/playlist.json`）跑通
  - [ ] 远程拉取（OkHttp）+ 本地缓存文件 + 24h 过期策略 + 失败重试
- [ ] `ChannelPlayerView` 封装播放区 + 频道信息条（台名/URL/加载进度）
- [x] **侧边频道菜单**（`PlaylistView` 首版）：确定键呼出，左侧浮层「左分类 + 右频道」两列垂直列表，**打开时视频继续播放**（不碰 GeckoView）。用 `MenuAdapter`（两列共用）+ RecyclerView 实现；菜单导航不走系统焦点，靠 `dispatchKeyEvent` 拦方向键后按下标渲染高亮（活动列高亮蓝、非活动列暗选中态）。
- [x] 记忆：上次观看频道（SharedPreferences，沿用 M0 的一维下标）。每台「上次使用的源序号」待多源落地后补。

**验收**：✅ 模拟器实测——OK 呼出菜单且视频不中断；左列切分类右列实时预览；频道列 OK 选台并加载（CCTV-13→CCTV-11 已验证）。多源切换待 M3。

### M3 — 稳健性与兼容性（决定能不能"给父母用"）
**目标**：自动换源、多内核、内存/崩溃治理。

> 2026-09-05 已确认小米电视 MiTV-MFTP0 的系统 WebView 66 与 CCTV 当前 MSE/WebRTC 播放器不兼容；UA 对齐、移动 UA、禁用 P2P、原生 HLS 回退和 MSE 时间戳偏移均无法同时满足起播与稳定播放。腾讯 X5 因服务端未向该设备下发内核而不可用，当前已改用随 APK 打包的 GeckoView 153，并通过真机播放、全屏、菜单和换台验证。完整记录见 [电视真机播放性能与兼容性排查](./电视真机播放性能与兼容性排查.md)。

- [ ] **加载超时自动换源**：进入等待态超过"最长加载时间"无心跳 → 切下一个源刷新
- [ ] **播放失败判定升级**：心跳 + 黑屏/无尺寸检测
- [ ] **多内核策略**：
  - [x] 接入 GeckoView 153，使用 ABI 拆包并以内置 WebExtension 完成页面适配；目标电视 3 分钟连续播放、全屏、菜单与换台验证通过
  - [x] 验证腾讯 X5：目标电视下载返回 -124、无法获得 X5 内核，不作为当前方案
  - [ ] 增加 GeckoView 内容进程崩溃恢复与长时间内存治理
  - [ ] 内核调试页（对应参考项目 TBS 调试界面）
- [ ] **站点适配器机制**：`WebpageAdapter` 抽象类 + `WebpageAdapterManager` 按 URL 匹配 + `CommonWebpageAdapter` 兜底（便于逐站点定制 UA / 选择器 / 进全屏方式）
- [ ] **内存治理**：限制 Gecko 内容进程、退到后台暂停 Session、长时间运行观察与必要时重建 Session
- [ ] 崩溃监控（Bugly 或其它）+ 匿名 UUID + 设备型号上报

**验收**：某源失效自动切换不黑屏；老设备/低版本 WebView 使用 GeckoView；长时间运行不崩。

## 5. 合规红线（务必前置，是这类产品的生存前提）
- 只**嵌套展示官网公开直播页**，不采集/存储/转发视频流，版权归原网站；
- 不破解登录 / 付费 / 清晰度限制；被限制访问时不绕过；
- 频道地址由用户收集提交，提供**侵权删除通道**；
- 明确**非营利**声明；保留完整《免责声明》页。
