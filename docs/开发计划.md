# WebTvLive 开发计划

> 目标：自研一款「基于 WebView 的安卓直播电视 App」，思路对齐参考项目 `WebViewTvLive`（用内置浏览器一键打开各电视台**官方直播网页**，自动定位网页里的 `<video>` 并进入全屏，做成"像传统电视一样换台"的体验）。本 App **不采集/不存储/不转发任何视频流**，只做官网页面的嵌套展示。

## 1. 产品原理回顾（决定技术选型）

```
用户选台 → WebView.loadUrl("about:blank")  // 先重置，清掉上一路视频
        → WebView.loadUrl(官网直播页URL)
        → onProgressChanged==100 → 注入适配 JS
        → JS 轮询找 <video> → 自动播放/取消静音/请求全屏 + 周期性"心跳"回调
        → 原生 WebChromeClient.onShowCustomView → 用 FrameLayout 容器按比例全屏
        → 超过"最长加载时间"无心跳 → 自动切下一个源并刷新
```

三个真正的技术难点（复刻成败在此，不在功能多少）：
1. **自动全屏可靠性**：不同网站进全屏方式不同 → JS 请求全屏 + 模拟按 `F` 键 + 模拟双击，多管齐下、重试若干次。
2. **内核兼容性**：安卓设备 WebView 版本碎片化严重 → 需要「系统 WebView / 腾讯 X5 / GeckoView」多内核策略（后期）。
3. **频道源服务端化**：官网 URL 会变 → 频道表放远程 JSON，客户端定期拉取，用户无感更新。

## 3. 分阶段里程碑

### ✅ M0 — 播放内核跑通（最小可玩）— **已完成并真机验证**
**目标**：自动加载 CCTV-13 官网直播页，全屏自动起播，遥控器返回键两次退出。

- [x] 确认 Kotlin 插件生效（能编译 `.kt`）→ **AGP 9.3.2 脚手架已内置 Kotlin，无需手动加 `org.jetbrains.kotlin.android`（手动加反而报 `extension 'kotlin' already registered`）**
- [x] `AndroidManifest.xml` 加 `INTERNET` + `usesCleartextTraffic="true"`；注册横屏 `MainActivity`（`sensorLandscape` + `configChanges` 防旋转重建 + LEANBACK 让 TV 启动器识别）
- [x] 全屏沉浸式（`WindowInsetsControllerCompat` 隐藏 systemBars）+ 屏幕常亮（`FLAG_KEEP_SCREEN_ON`）
- [x] 布局：根 `FrameLayout`（黑底）含 WebView 容器 + 全屏视频兜底容器 `fullscreenContainer`
- [x] 封装 WebView：JS/DOM 开启、`mediaPlaybackRequiresUserGesture=false`、桌面 UA、`mixedContentMode=ALWAYS_ALLOW`、进度 100 + `onPageFinished` 双重注入、`onShowCustomView` 兜底、`onReceivedSslError` 放行
- [x] `addJavascriptInterface` 暴露 `AndroidTV`（`notifyVideoPlaying()` / `setVideoSize()`）
- [x] `assets/default_js_template.js`：轮询挑最大 `<video>` → 全屏铺满 → 强制播放 + 心跳
- [x] 自动加载 `https://tv.cctv.com/live/cctv13/`（`HOME_URL` 常量）
- [x] 返回键两次退出（`onKeyDown` 拦 `KEYCODE_BACK`，2s 内两次 `finish()`）

**验收**：✅ 模拟器（Android 12 / SDK 32）实测——自动起播、视频铺满全屏、导航栏隐藏；横屏不旋转；返回键两次退出。

> **全屏方案关键结论（踩坑记录，务必保留）**：
> 1. **不能只用 `<style>` 铺满**：目标 `<video>` 的祖先元素带 `transform`，会让 `position:fixed` 不再相对视口 → 必须**清除祖先链的 `transform/filter/perspective`**。
> 2. **不能依赖 `<style>` 的 `!important`**：CCTV 播放器脚本每帧用**内联样式**把 video 尺寸改回 `1138×640`，内联优先级更高 → 必须**每秒把 `!important` 内联样式直接写到 video 元素上**（`style.setProperty(k,v,'important')`）压过站点脚本。
> 3. **隐藏网页外壳**：把 body 下不在「video→body 祖先链」上的顶层节点 `display:none`，只留播放器这一支 DOM，导航栏/边栏才会消失。
> 4. **WebView 不要开 `useWideViewPort/loadWithOverviewMode`**：桌面 UA 下它们会整页缩放，导致 `100vw/100vh` 与真实可视区不一致、铺不满。
> 5. 全屏靠「JS 每秒维护内联样式（自愈）」实现，`onShowCustomView` 仅作原生全屏站点的兜底。

### M1 — 频道体系（换台）
**目标**：内置/远程频道表，列表选台、上下键换台、多源切换。

- [ ] 数据模型：`Channel(name, group, urls: List<String>)`、`ChannelGroup`、`Playlist`
- [ ] `PlaylistManager`：
  - [ ] 先内置一份本地 JSON（`assets/playlist.json`）跑通
  - [ ] 远程拉取（OkHttp）+ 本地缓存文件 + 24h 过期策略 + 失败重试

- [ ] `PlaylistView`（RecyclerView）：分组分页、选中项高亮、点击选台

**验收**：从列表选台可播；上下键顺畅换台；同一台可在多个官网源间切换。

### M3 — 稳健性与兼容性（决定能不能"给父母用"）
**目标**：自动换源、多内核、内存/崩溃治理。

- [ ] **加载超时自动换源**：进入等待态超过"最长加载时间"无心跳 → 切下一个源刷新
- [ ] **播放失败判定升级**：心跳 + 黑屏/无尺寸检测
- [ ] **多内核策略**：
  - [ ] 接入腾讯 X5（TBS SDK），支持系统/X5 切换 + 在线安装内核入口
  - [ ] 评估 GeckoView 作为备选（"火狐版"）
  - [ ] 内核调试页（对应参考项目 TBS 调试界面）
- [ ] **站点适配器机制**：`WebpageAdapter` 抽象类 + `WebpageAdapterManager` 按 URL 匹配 + `CommonWebpageAdapter` 兜底（便于逐站点定制 UA / 选择器 / 进全屏方式）
- [ ] **内存治理**：定时重建 WebView、退到后台释放、`about:blank` 重置
- [ ] 崩溃监控（Bugly 或其它）+ 匿名 UUID + 设备型号上报

**验收**：某源失效自动切换不黑屏；老设备/低版本 WebView 可切 X5 播放；长时间运行不崩。

## 5. 合规红线（务必前置，是这类产品的生存前提）
- 只**嵌套展示官网公开直播页**，不采集/存储/转发视频流，版权归原网站；
- 不破解登录 / 付费 / 清晰度限制；被限制访问时不绕过；
- 频道地址由用户收集提交，提供**侵权删除通道**；
- 明确**非营利**声明；保留完整《免责声明》页。
